# Character pipeline

Общие скрипты для Blender 5.2.2 и Unreal Engine 5.8. Модель не размещается на уровне.

В режиме **Cmd** консоли уже открытого Unreal проекта ArcheoDig:

```text
py "D:/UEProject/ArcheoDig/Tools/BlenderToUE/characters/run.py" --npc EllieRowan --mode all
```

Это одна команда для `Validate → Export → Import/Reimport → Validate`. Blender должен быть
открыт с нужным `.blend` и работающим существующим MCP add-on. Подключение берётся из
`.codex/config.toml`; новый редактор или MCP server не запускаются. В Python console
можно также вызвать `run.run('EllieRowan', 'all')` после добавления этой папки в `sys.path`.

Режимы:

- `validate`: только проверка текущей сцены и обнаруженного исходного скелета UE.
- `export`: проверка, FBX и обратное чтение FBX; UE-ассеты не меняются.
- `all`: полный процесс; при наличии целевого SkeletalMesh обновляется тот же путь.
  Если вычисленная геометрия, конфигурация, FBX, исходный Skeleton и сохранённый целевой
  ассет не изменились, экспорт/импорт пропускаются после проверки текущего ассета.
- `reimport`: принудительный полный процесс с обязательным наличием целевого ассета.

`characters.json` — единственная конфигурация персонажей этого конвейера. Чтобы добавить
NPC на том же Quinn, добавьте запись: исходник, Armature, положительный список коллекций,
исключения, точный путь SkeletalMesh и папку Materials. Копировать Python-скрипты не нужно.
Профиль Quinn хранит **имя** исходного меша; его Skeleton каждый раз определяется через
Asset Registry и `SKM_Quinn_Simple.skeleton`, путь скелета не задан в конфигурации.

Экспортируется живая сцена, включая несохранённые изменения. `.blend` не сохраняется.
Скрытая исходная Quinn исключается явно; отображение очков `hide_set` не исключает их
из экспорта, если они участвуют в рендере. Камеры, Empty и helper-объекты не экспортируются.
Все модификаторы вычисляются на временных копиях; текущая поза должна быть нейтральной.

Исходная сцена остаётся в метрах. Копии переводятся в сантиметры в временной сцене,
затем удаляются. Это даёт корневую кость с масштабом 1. Стандартный FBX exporter
использует `-Y Forward / Z Up`, без анимаций и leaf bones. Только сериализованное имя
временной Armature переопределяется на имя корневой кости: исходный объект не переименовывается.
При изменении экспортёра Blender результат проверяется повторным чтением FBX до импорта UE.
Rest Pose, имена, родители и масштаб должны совпасть с исходной Quinn; допускается лишь
численная погрешность 0,002 см / 0,02°. В Blender 88 внутренних костей, FBX/UE имеют
дополнительную корневую `root` — всего 89. Дополнительные corrective bones общего
Skeleton не копируются и не меняются.

Импорт повторяет рабочий подход RudyPawnshop: принудительный `FbxFactory`, временное
отключение FBX Interchange, `save=False`, затем явная проверка и сохранение нужных ассетов.
Опции изменения Skeleton Reference Pose, T0 pose, анимаций, нового PhysicsAsset отключены.
Перед/после проверяются хеш Reference Pose полного Skeleton, файлы Skeleton/Quinn,
набор новых/dirty packages, dirty maps, геометрические границы и структура импортированного меша.
Смена состава/порядка material slots останавливает повторный импорт. Имеющиеся назначения,
включая пользовательские материалы вне папки NPC, сохраняются.

При первом импорте создаются простые PBR-материалы из основных значений Blender;
цвет лица использует vertex colors. **Процедурные текстуры, сложные ноды, пряди/узоры
и мимика не запекаются этим конвейером.** При отсутствии UV на экспортных копиях
создаётся техническая box-развёртка; она не заменяет художественную UV-развёртку.
Новые материалы не перезаписываются при повторном импорте.

FBX находится рядом с исходным `.blend`. Подробности и ошибки:
`Saved/BlenderToUE/Characters/<NPC>/{reference,export,import,result}.json`, `error.txt`.
На ошибке до импорта ассеты не меняются. Если постпроверка импорта не проходит,
результат остаётся **несохранённым** в редакторе, исключение записывается в лог;
автоматического отката/удаления ассетов нет. Внешность персонажа конвейер не правит.

Проверки без редакторов: `python -m unittest discover -s Tools/BlenderToUE/characters -p test_safety.py`.
