# Blender → UE5 Building Workflow

Статус: **текущий workflow — отдельная проработка зданий и модульная система; исторический blockout сохранён ниже**.

С 2026-10-01 Blender используется как отдельный инструмент для создания и правки 3D-макетов зданий перед размещением в Unreal Engine.

## Зачем добавлен Blender

Первый университет был собран напрямую в UE5 большим количеством отдельных Static Mesh Actor'ов. Для быстрого прототипа это сработало, но для дальнейших итераций оказалось неудобно:

- изменение общей формы требует править много отдельных частей;
- Outliner быстро разрастается;
- сложнее масштабировать фасад, крышу и пропорции как единое здание;
- неудобно использовать такую сборку как повторно редактируемый source asset.

Поэтому принято разделение:

~~~text
Blender
→ создание и редактирование самого здания

Unreal Engine 5
→ расстановка зданий
→ проверка масштаба персонажем
→ дороги / город / gameplay
~~~

Blender не заменяет UE5 level design. Весь город по-прежнему собирается в Unreal.

## Новое решение: модульное производство зданий перед финальной сборкой города (2026-11-07)

Первичная расстановка готовых зданий и заглушек на `Level_6` позволила определить примерную композицию города. Дальнейшие глобальные перестановки заглушек **не являются текущим приоритетом**. Сцена остаётся рабочим прототипом и сохраняется без удаления.

Теперь работа идёт **по одному зданию**, с проектированием его функций до окончательного утверждения размеров:

1. Зафиксировать роль конкретного здания в геймплее: что игрок делает внутри или рядом с ним, какие зоны нужны, какие помещения доступны.
2. Спроектировать план этажей, дверей, лестниц и основных проходов с размерами (например, в Figma). Для фоновых зданий полноценный интерьер не требуется.
3. Собрать минимальный функциональный прототип доступных помещений и проверить удобство в UE5 с персонажем; **габариты пока могут меняться**.
4. Уточнить внешний архитектурный объём и создать/доработать редактируемый `.blend`, опираясь на модульные детали и сохраняя уникальность значимых зданий.
5. Перенести/обновить модель согласно `Docs/Technical/BlenderToUE_ImportRules.md`, проверить размеры, проходимость, материалы и необходимые взаимодействия.
6. Только после проверки закрепить фактические размеры корпуса, выступающих деталей и участка раздельно; затем использовать их для итогового генплана.
7. Когда важные здания проработаны, **собрать/адаптировать кварталы и улицы** на Level_6 по реальным размерам; не подгонять помещения под устаревшие габариты заглушек.

**Модульная система**: переиспользуемые фасадные секции, стены, угловые элементы, окна, двери, карнизы, крыши, пристройки, лестницы, ограды и другие повторяющиеся части. Позже — при необходимости — модули тротуаров, мощения, переулков, дворов и малых площадей. Модули должны быть предсказуемыми по размерам, точкам стыковки, осям/ориентации и материалам. Не нужно ради каждого здания делать независимый набор одинаковых деталей.

Три уровня подробности:

- **Игровое здание:** прорабатываем нужные планировки, доступные комнаты, взаимодействия и внешнюю архитектуру.
- **Частично игровое:** прорабатываем только реально используемые интерьеры/помещения и внешние зоны.
- **Фоновое:** используем архитектурные модули и силуэт, **без обязательного интерьера**.

Новые модули и ассеты делаем переиспользуемыми, не привязанными к Level_6. Утверждённое расположение сюжетных объектов сохраняем как ориентир для городской композиции, но размеры и итоговая расстановка уточняются после проверки функций зданий.

Важно: существующие `.blend`, импортированные UE-ассеты и текущий Level_6 **не удалять и не пересоздавать**. Перед изменением конкретной модели проверять её актуальный источник и состояние импорта.

## Инструменты

Текущая связка:

- **Blender 5.2.2 LTS**;
- официальный **Blender Lab MCP add-on 1.0.3**;
- локальный MCP Bridge: localhost:9875;
- Codex / Astra управляет Blender через MCP;
- сервер запускается через uv;
- проектный MCP config находится в .codex/config.toml.

Blender и UE MCP могут использоваться в одном проекте: Astra может отдельно работать со сценой Blender и с Unreal.

## Базовый pipeline здания (первоначальный blockout)

~~~text
1. Game Design docs
   ↓
2. Размер / этажность / роль
   ↓
3. Визуальный reference
   ↓
4. Astra строит editable модель в Blender
   ↓
5. Проверка формы и пропорций в Blender
   ↓
6. FBX export
   ↓
7. Import как Static Mesh в UE5
   ↓
8. Проверка рядом с персонажем и другими зданиями
   ↓
9. Правка исходного .blend
   ↓
10. Re-export / Reimport
~~~

Эта последовательность описывает **первоначальный blockout / city mockup workflow**. В текущем процессе ей предшествует функциональное проектирование здания и подтверждение необходимых помещений и размеров; см. раздел «Новое решение» выше.

## Правила для ранних blockout-моделей (исторический этап)

В Blender важнее всего:

- правильный footprint;
- этажность;
- высота;
- общий силуэт;
- окна и входы в правильном масштабе;
- крыша и крупные архитектурные элементы;
- понятная структура объектов.

Для **ранних наружных заглушек** не требовались:

- полноценные интерьеры;
- high-poly;
- сложная UV-развёртка;
- production textures;
- игровые двери;
- сложная collision setup;
- финальные LOD.

Исходный .blend должен оставаться редактируемым. Если для UE нужен единый mesh, объединение выполняется только на экспортной копии / этапе экспорта.

## Организация Blender-сцены

Для каждого здания желательно:

~~~text
BLD_BuildingName
└── BuildingName_ROOT
    ├── Walls
    ├── Roof
    ├── Windows
    ├── Doors
    ├── Trim
    └── Props
~~~

ROOT:

- находится в центре здания на уровне земли;
- используется для перемещения всей сборки;
- все части здания parent'ятся к нему.

Перед экспортом:

- ground min Z = 0;
- Rotation / Scale применены;
- нормали проверены;
- экспортируется только здание;
- Camera / Light / helper objects не экспортируются.

## Blender и Unreal выглядят по-разному

Это важный вывод первого импорта общежития.

Один и тот же объект может заметно отличаться визуально из-за:

- Blender AgX / viewport lighting;
- UE tonemapper и exposure;
- Directional Light / SkyLight / Atmosphere;
- отличий Blender shader nodes от UE materials;
- ограниченного переноса материалов через FBX.

Поэтому:

**геометрию и базовую палитру удобно создавать в Blender, но финальный внешний вид здания оценивается в UE5.**

Для blockout желательно использовать простые материалы:

- Base Color;
- Roughness;
- Metallic;
- минимум сложных Blender-only shader effects.

Позже полезно сделать отдельный UE level L_BuildingPreview с фиксированным светом и exposure, чтобы все здания сравнивались в одинаковых условиях.

## Важный художественный вывод

Первый вариант общежития с плоской крышей, кондиционерами и техническим оборудованием визуально получился слишком похожим на современную школу / административное здание.

После правки текущая модель получила:

- тёплый кирпич;
- светлую каменную отделку;
- тёмную скатную крышу;
- центральное крыльцо;
- более спокойный университетский характер.

Правило для campus-зданий:

~~~text
University = богатый исторический landmark
Dormitory = более простой функциональный родственник того же ансамбля
~~~

При этом не нужно буквально копировать архитектуру университета.
