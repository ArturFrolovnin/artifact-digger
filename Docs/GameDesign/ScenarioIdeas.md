# ArcheoDig — Scenario Ideas

> Этот файл содержит **сырые идеи, варианты и референсы**.
> Наличие записи здесь **не означает**, что решение утверждено для игры.
> После обсуждения принятые решения переносятся в [Scenario.md](Scenario.md).
>
> Текущий принцип работы: сначала максимально полно собрать идеи по городу, лору, персонажам и gameplay systems, затем отдельно пройтись по ним, поправить, сократить и только после этого переносить подтверждённое в утверждённый сценарий.

# 1. Visual / Style References

## Main reference — Chop Chop Inc

**Chop Chop Inc** — основной визуальный референс для ArcheoDig на текущем этапе.

Что нравится как направление:

- общая стилистика;
- читаемые формы;
- приятный, не фотореалистичный visual language;
- стиль хорошо подходит небольшой indie-игре с плотным интерактивным городком;
- использовать игру как главный reference point при обсуждении визуального языка ArcheoDig.

Позже отдельно разобрать, что именно стоит брать как ориентир:

- формы зданий;
- материалы;
- освещение;
- окружение;
- UI;
- пропорции объектов;
- плотность деталей.

Не копировать стиль буквально.

## Secondary reference — PowerWash Simulator 2

**PowerWash Simulator 2** — дополнительный визуальный/атмосферный референс.

Особенно потенциально полезен для:

- приятного ощущения очистки предметов;
- реставрации;
- визуального перехода «грязный предмет → красивый восстановленный предмет»;
- спокойного satisfying gameplay.

## Town scale reference — Internet Cafe Simulator 2

Город должен быть **компактным и плотным**, а не большим open world.

Референс по ощущению масштаба — городок из **Internet Cafe Simulator 2**, но ArcheoDig можно сделать примерно в **1.5–2 раза насыщеннее/крупнее по содержимому**.

Главный принцип:

```text
маленькая территория
+ много полезных зданий
+ постоянно ходят NPC
+ короткие маршруты
+ ощущение живого места
```

Город не должен быть рассчитан на автомобильное управление. Игрок перемещается по нему пешком.

# 2. Общая структура мира

## Town = отдельный hub level

Город — главный постоянный уровень, куда игрок возвращается между экспедициями.

В городе находятся:

- музей;
- жильё;
- магазины;
- NPC;
- социальные активности;
- экономика;
- подготовка к экспедициям.

## Dig Sites = отдельные уровни

Места раскопок — отдельные levels.

Примерно:

```text
Town
→ выбрать экспедицию
→ loading
→ Dig Site
→ раскопки
→ возвращение
→ Town
```

Каждый Dig Site может иметь:

- собственный тип грунта;
- уникальное окружение;
- свои находки;
- собственные hazards;
- отдельные quest objectives.

Это позволяет не строить один огромный open world и держать editable voxel terrain только там, где он реально нужен.

# 3. Основная сюжетная завязка

## Главный герой

Главный герой — молодой человек, недавно закончивший университет.

Рабочее направление: он учился на археолога / смежную специальность и после выпуска едет в небольшой город к деду, рассчитывая пройти у него практику и поучаствовать в настоящих раскопках.

## Начальная сцена

Идея начала:

```text
автобус
→ герой едет в город
→ вспоминает окончание университета
→ думает о будущем
→ радуется возможности работать с дедом
→ приезжает
```

Не делать длинную катсцену. Скорее короткое атмосферное введение.

## Дед

Дед — один из ключевых персонажей всей игры.

Его роли:

- родственник;
- наставник;
- главный источник археологических знаний;
- источник лора;
- один из главных quest givers;
- эмоциональный центр сюжета;
- персонаж, связанный с финальным выбором.

После приезда герой узнаёт, что ситуация изменилась.

## Пожар в музее

В городе произошёл пожар в музее.

Музей закрыт или сильно пострадал, значительная часть коллекции потеряна/уничтожена.

Дед вместо обычной практики предлагает герою помочь:

```text
научиться реальным раскопкам
→ искать новые находки
→ восстанавливать коллекцию
→ постепенно вернуть музей к жизни
```

Первые раскопки одновременно являются tutorial.

Дед обучает:

- как копать;
- как обращаться с находками;
- как понимать грунт;
- как пользоваться инструментами;
- как отличать обычную вещь от исторически важного предмета.

Дед периодически звонит/пишет игроку и подкидывает интересные точки раскопок.

Пример направления:

> «Я тут нашёл старую запись. В таком-то месте когда-то находили вещи с похожей символикой. Съезди посмотри.»

# 4. Главная тайна / легендарный артефакт

После начального этапа восстановления музея игрок находит необычную вещь:

- карту;
- табличку;
- часть древнего предмета;
- ключ;
- фрагмент механизма;
- другой след древней легенды.

Точная форма пока не определена.

Дед узнаёт символику/историю и удивляется, потому что раньше считал эту легенду мифом.

Рабочая структура:

```text
обычные раскопки
→ необычная находка
→ дед узнаёт легенду
→ серия специальных экспедиций
→ новые части загадки
→ поиск главного артефакта
→ финальный выбор
```

Конкретную цивилизацию, эпоху, историю и природу артефакта придумать позже.

Главное: легенда постепенно должна вырастать из обычной археологической работы, а не появиться отдельной «эпической» сюжетной линией из ниоткуда.

# 5. Финальный артефакт — варианты применения

Точная природа артефакта пока не определена, но он должен обладать исключительной способностью, которая позволяет сделать один серьёзный выбор.

Рабочие варианты финального решения:

## 1. Дед

Использовать артефакт на деде.

Не обязательно спасать его от внезапной смертельной болезни. Идея скорее в том, чтобы:

- вылечить накопившиеся возрастные проблемы;
- вернуть здоровье;
- вернуть молодость/жизненные силы;
- дать деду возможность снова путешествовать;
- продолжить приключения вместе с внуком.

Эмоциональная награда:

```text
ещё много лет вместе
→ новые путешествия
→ дружба
→ совместная археология
```

## 2. Романтический / личный выбор

Использовать возможность артефакта ради личной романтической линии / личного счастья героя.

**Точную механику и этическое оформление нужно придумать позже.**

Не фиксировать сейчас буквальную механику «заставить человека полюбить героя».

## 3. Город

Сделать артефакт достоянием города.

Рабочий образ — что-то вроде **«фонтана жизни»** или другой публичной установки.

Эффект может быть связан со здоровьем:

- лечить болезни;
- подавлять вирусы;
- улучшать здоровье жителей;
- превратить город в уникальное место.

Это связывает финал с городом, который игрок всю игру постепенно узнавал и развивал.

## 4. Деньги

Продать артефакт.

Игрок становится чрезвычайно богатым и выбирает личную финансовую свободу.

Не обязательно подавать этот вариант как «плохую концовку».

# 6. Главный gameplay loop

Рабочий цикл:

```text
город
→ подготовка
→ выбрать Dig Site
→ экспедиция
→ раскопки
→ находки
→ возвращение

важные исторические находки
→ музей

обычные ценные вещи
→ реставрация / ломбард

деньги
→ инструменты / дом / мастерская / машина / другие улучшения

→ следующая экспедиция
```

# 7. Экономика

## Источники денег

Основное направление:

- обычные ценные находки;
- золотые/серебряные мелочи;
- кольца;
- часы;
- монеты;
- украшения;
- другие вещи, которые не обязательно нужны музею;
- продажа через ломбард;
- позже — повышение цены через реставрацию.

## Основные money sinks

Рабочий список:

- инструменты;
- одежда;
- экспедиционное снаряжение;
- расходники;
- кофе/еда;
- улучшения дома;
- мастерская;
- машина;
- потенциальные улучшения музея;
- лечение / спасательные операции;
- развлечения в городе;
- бар / азартные игры.

Экономика должна создавать выбор:

```text
потратить деньги на себя сейчас
или
вложиться в долгосрочное улучшение
```

# 8. Телефон как in-world UI

У героя есть смартфон, который работает как основной diegetic interface.

Возможные разделы:

- Inventory;
- Messages;
- Calls;
- Contacts;
- Quests / Notes;
- News;
- карта / Dig Sites;
- информация об экспедиции;
- музей;
- Emergency / Rescue.

Дед и другие NPC могут звонить и писать через телефон.

Телефон также нужен как безопасный системный выход из проблемных ситуаций.

# 9. Путешествия и подготовка к экспедициям

## Автобусная остановка

В начале основной способ поездки на раскопки — остановка/транспортная точка.

Игрок:

```text
подходит к остановке
→ выбирает Dig Site
→ собирает ограниченный набор вещей
→ тратит часть stamina/ресурса путешествия
→ переходит на другой level
```

Игрок должен планировать экспедицию заранее.

## Ограниченный expedition inventory

Нельзя брать с собой всё имущество.

Перед поездкой нужно выбирать:

- инструменты;
- еду;
- кофе;
- одежду;
- фонарь;
- расходники;
- другое оборудование.

Это создаёт подготовительный gameplay.

# 10. Машина — НЕ управляемый транспорт

Важное scope-решение:

**Игрок не водит автомобиль вручную.**

Не делать:

- driving gameplay;
- автомобильную физику;
- полноценную дорожную сеть;
- AI traffic;
- парковочный gameplay.

Машина — статичный объект и progression system.

## Роль машины

```text
дом / гараж
→ машина
→ expedition loadout
→ Dig Site
```

Машина даёт:

- расширенный инвентарь;
- багажник;
- возможность брать больше снаряжения;
- снижение stamina cost путешествия;
- потенциальный доступ к более далёким / сложным Dig Sites;
- ощущение прогресса.

На Dig Site машина может появляться как статичный объект в стартовой зоне.

Игрок может подходить к ней и пользоваться багажником, но не управлять автомобилем.

# 11. Жильё игрока

## Начало

В начале герой живёт:

- либо в маленькой комнате у деда;
- либо вместе с дедом в его доме.

Точный вариант позже определить.

## Покупка собственного дома

Достаточно рано игрок получает возможность купить собственный дом.

Это крупный progression milestone.

Дом нужен не только для косметики.

Возможные системы дома:

- спальня;
- кровать;
- storage;
- мастерская;
- гараж / место для автомобиля;
- кабинет;
- декоративные предметы;
- личные памятные находки.

## Сон

Сон влияет на состояние игрока.

Например:

- восстановление stamina;
- качественная кровать даёт лучшее восстановление;
- улучшения спальни могут давать небольшие бонусы на следующий день.

Не превращать это в тяжёлую RPG-систему.

# 12. Мастерская / реставрация

Мастерская находится в доме игрока или является его улучшением.

## Ручная реставрация

Игрок может привезти найденную обычную ценную вещь:

```text
грязный / повреждённый предмет
→ очистка
→ реставрация
→ улучшение состояния
→ увеличение стоимости
```

Пример идеи:

```text
грязная старая ложка
→ очистка
→ выясняется, что она серебряная
→ после реставрации стоит значительно дороже
```

Рабочее направление: восстановленный предмет может продаваться условно в 2 раза дороже, но точный баланс определить позже.

## Развитие мастерской

Возможные улучшения:

- стол;
- инструменты;
- химия;
- точное оборудование;
- разные способы очистки;
- профессиональное оборудование.

## Работники

В late game игрок сможет нанимать людей.

Идея:

```text
ранняя игра
→ игрок реставрирует сам

позже
→ нанятый реставратор
→ очередь предметов

ещё позже
→ автоматическая реставрация обычного loot
→ возможно автоматическая продажа
```

Работники могут открываться через отношения / знакомство / progression.

Редкие, музейные и сюжетные предметы не должны автоматически продаваться.

# 13. Город — размер и устройство

Город должен ощущаться живым, но **не быть громоздким**.

Не нужен большой open world.

Принцип:

- всё достаточно близко;
- короткие пешие маршруты;
- много NPC;
- здания имеют понятное назначение;
- часть домов/многоэтажек — визуальный фон;
- игрок быстро запоминает город.

Город проектируется под пешее передвижение.

Если появляются дороги, они в основном визуальные/атмосферные, а не для player driving.

На границах можно использовать:

- повороты;
- закрытые улицы;
- визуальные продолжения города;
- background buildings;
- простые заглушки.

# 14. Черновой реестр ключевых зданий / локаций

Этот список **ещё не полный**.

## 1. Музей

Главная сюжетная точка.

Функции:

- дед;
- сюжет;
- коллекция;
- восстановление после пожара;
- сдача важных артефактов;
- лор;
- визуальный прогресс всей игры.

Идея: по мере прохождения музей физически заполняется экспонатами и начинает оживать.

## 2. Дом деда / стартовое жильё

Функции:

- начало игры;
- отношения с дедом;
- стартовая комната героя;
- tutorial бытовых систем;
- часть сюжетных сцен.

## 3. Дом игрока

Покупаемый дом.

Функции:

- сон;
- storage;
- мастерская;
- машина;
- личные трофеи;
- улучшения;
- социальная жизнь района.

## 4. Ломбард

Работает в первую очередь как **место продажи обычных ценных находок**.

Не основной магазин для покупки.

### Ломбардщик

Харизматичный язвительный мужик.

В начале:

- недоволен игроком;
- токсично шутит;
- относится как к очередному «шкету»;
- может пытаться давать менее выгодную цену.

Со временем отношение улучшается.

Пример progression отношения:

```text
«Что ты сюда принёс?»
→
«О, шкет, опять ты.»
→
«Давай сюда, посмотрим, что нашёл.»
→
нормальное уважение / дружеская токсичность
```

Позже может:

- давать более честные цены;
- делиться слухами;
- давать необязательные наводки;
- придерживать вещи для игрока.

## 5. Магазин снаряжения

Главный магазин подготовки к экспедициям.

Продаёт:

- лопаты;
- кирки;
- инструменты;
- фонари;
- одежду;
- кофе;
- еду;
- расходники;
- рюкзаки;
- другое expedition gear.

Продавец — отдельный персонаж, характер пока не утверждён.

## 6. Автомагазин

Продаёт машины.

Машины сравниваются как gameplay upgrades:

- объём багажника;
- expedition capacity;
- travel stamina efficiency;
- потенциальный доступ к некоторым локациям.

### Девушка из автомагазина

Одна из романтических линий.

Рабочий образ:

- уверенная;
- кокетливая;
- хорошо разбирается в машинах;
- объясняет игроку характеристики;
- знакомит с транспортной progression system;
- может слегка подкалывать героя.

В дальнейшем у неё должна быть собственная personality и quest line.

## 7. Автобусная остановка / travel point

Функция:

- выбор Dig Site;
- переход между уровнями;
- стартовый способ путешествий.

## 8. Бар

Не обязательная сюжетная точка.

Роль:

- атмосферное место;
- жители города отдыхают;
- социальный фон;
- необязательные interactions;
- место, где игрок может тратить деньги;
- возможные мини-игры.

Дополнительно:

- скрытая/тайная комната;
- азартные игры на деньги;
- более сомнительная сторона городка.

Бар не обязан быть важным для основного квеста.

## 9. Больница

Функции:

- recovery;
- fail state;
- rescue system;
- возможные медицинские NPC;
- часть темы здоровья города.

Подробная система поражения описана ниже.

## 10. Дом соседки

Дом расположен **рядом с домом игрока**.

Это важная социальная точка.

### Соседка

Основная / официальная сюжетная романтическая линия.

Рабочий образ:

- приятная;
- доброжелательная;
- домашняя;
- спокойная;
- работает удалённо;
- условно бухгалтер / специалист по бумажной работе;
- почти всегда находится дома или рядом;
- гуляет с собакой;
- может сидеть во дворе / на газоне.

Interactions:

- разговоры;
- подарки;
- небольшие бытовые задания;
- choices;
- отношение может улучшаться или ухудшаться.

Отношения должны развиваться постепенно.

Собака может естественно помочь первому знакомству.

## 11. Частный жилой квартал

Дом игрока и дом соседки не должны стоять вдвоём в пустоте.

Нужен небольшой квартал примерно на **6–8 домов**.

Это отдельный уютный residential pocket города.

Рабочая структура:

- дом игрока;
- дом соседки;
- ещё несколько домов с яркими фоновыми персонажами.

Примеры соседей — пока только идеи:

- дед-конспиролог в шапочке из фольги;
- пара пожилых хиппи, которые пытаются «вернуть молодость»;
- весёлые раздолбаи / пранкеры, постоянно делающие что-то странное на газоне;
- добрый местный выпивоха / философ;
- растаманский/расслабленный персонаж;
- слишком правильный сосед, который раздражается от остальных.

Эти NPC в основном фоновые.

Им не нужны большие quest chains.

Достаточно:

- коротких диалогов;
- бытовых сценок;
- маленьких просьб;
- случайных взаимодействий;
- узнаваемого поведения.

Цель — создать ощущение «моего района».

## 12. Многоквартирные дома / background housing

В городе должны быть и обычные многоэтажные/многоквартирные здания.

Большинство из них могут быть:

- background;
- источником NPC;
- неинтерактивными;
- создавать ощущение, что город больше реальной gameplay зоны.

## 13. Церковь

Пока только идея здания для города.

Точная gameplay/сюжетная функция ещё не определена.

Может быть:

- частью визуального силуэта города;
- местной исторической точкой;
- атмосферной локацией;
- потенциальным источником lore.

## 14. Библиотека

Библиотека — **важная progression location**, а не просто атмосферное здание.

Основная идея: часть характеристик героя развивается естественно через действия, а интеллектуальные/социальные навыки можно дополнительно развивать через обучение в библиотеке.

Библиотека потенциально отвечает за:

- знания;
- оценку находок;
- понимание реальной стоимости предметов;
- археологические/исторические знания;
- более выгодные сделки;
- дополнительные варианты диалогов;
- возможность лучше располагать к себе NPC;
- потенциальное открытие новых сведений о находках и Dig Sites.

Пример экономической связи:

```text
нашёл предмет
→ плохо разбираешься
→ не знаешь его реальную цену
→ ломбардщик получает преимущество

учишься / развиваешь знания
→ лучше оцениваешь предмет
→ понимаешь его ценность
→ можешь торговаться / получать более выгодную цену
```

### Как выглядит обучение

Не делать отдельный сложный симулятор учёбы.

Рабочая идея:

```text
игрок приходит в библиотеку
→ выбирает обучение
→ короткий timer / символическая transition
→ UI показывает, что герой читает / учится
→ время проходит
→ характеристика получает progression
```

Можно использовать простую визуальную заставку/иконку вместо полноценной анимации.

## 15. Спортзал

Спортзал — физическая progression location.

Он может развивать:

- stamina;
- физическую выносливость;
- потенциально силу;
- скорость восстановления;
- эффективность работы тяжёлыми инструментами.

Как и библиотека, спортзал не требует сложной playable mini-game.

Рабочая подача:

```text
зашёл
→ выбрал тренировку
→ короткая icon/transition animation
→ прошло игровое время
→ progression увеличилась
```

Важно: спортзал не должен быть единственным способом развития физических характеристик. Основная идея — герой также естественно становится выносливее от реальной работы и раскопок.

## 16. Парикмахерская

Парикмахерская — простая cosmetic/social location.

Функции:

- изменить причёску / внешний вид;
- потенциально другие косметические настройки;
- дополнительное ощущение живого города.

Не нужен полноценный процесс стрижки.

Рабочая подача:

```text
игрок выбирает вариант
→ короткая transition / иконка стрижки
→ проходит немного времени
→ новый внешний вид применяется
```

Это пример общего scope-принципа города: **не каждая активность требует полноценной анимационной системы и отдельного gameplay loop**.

# 15. Район игрока

Рабочее ощущение:

```text
городской центр
→ магазины / музей / бар / общественные здания

чуть в стороне
→ небольшой частный квартал
→ 6–8 домов
→ дом игрока
→ соседка
→ запоминающиеся фоновые соседи
```

Район должен быть достаточно маленьким, чтобы игрок быстро знал всех в лицо.

# 16. NPC и отношения

Не каждый NPC должен быть quest giver.

Условные уровни:

## Key characters

- дед;
- соседка;
- девушка из автомагазина;
- другие будущие сюжетные персонажи.

Имеют полноценные relationships / quest arcs.

## Functional characters

- ломбардщик;
- продавец снаряжения;
- врачи;
- другие владельцы полезных точек.

Имеют характер и progression отношений, но могут быть менее сюжетными.

## Ambient characters

- соседи;
- посетители бара;
- жители города;
- люди на улицах.

Нужны прежде всего для ощущения живого города.

# 17. Опасности на Dig Sites

Игра не обязана быть combat-oriented.

Но на раскопках могут быть environmental hazards:

- животные;
- волки;
- падение;
- обвал;
- истощение;
- неправильное планирование;
- застревание в раскопе.

Животные скорее часть мира/опасности, а не классические враги.

# 18. Hospital / Rescue Fail State

Основное правило поражения:

**Игрок не теряет найденные вещи, артефакты или оборудование.**

Если герой:

- теряет всё здоровье;
- получает критическую травму;
- условно «умирает»;
- попадает под обвал;
- получает серьёзный урон от животного;
- застревает в terrain и сам вызывает rescue,

срабатывает спасательная служба.

```text
поражение / критическая травма / застревание
→ спасатели
→ эвакуация
→ больница
→ полное восстановление
→ всё снаряжение и находки сохранены
→ денежный счёт
→ игрок продолжает игру
```

## Что сохраняется

Спасатели забирают вместе с игроком:

- инструменты;
- инвентарь;
- loot;
- найденные артефакты;
- важные предметы.

Никакой случайной потери редкой находки после поражения.

## Наказание

Основное наказание — деньги.

Игрок получает счёт:

- за работу спасателей;
- за эвакуацию;
- за лечение.

Точная система стоимости будет придумана позже.

Цена может потенциально зависеть от:

- места;
- дальности;
- сложности спасательной операции;
- характера происшествия;
- других факторов.

Цель системы:

- ошибки должны иметь цену;
- игрок должен планировать экспедиции;
- поражение не должно уничтожать прогресс;
- найденный редкий артефакт не должен пропадать из-за случайного fail state.

# 19. Музей как визуальный прогресс игры

Рабочая идея:

в начале музей после пожара пустой/повреждённый.

По мере игры:

```text
первые находки
→ первые витрины
→ новые экспонаты
→ новые залы
→ посетители
→ музей оживает
```

Музей становится визуальным progress bar прохождения.

Возможные будущие улучшения:

- витрины;
- реставрационная зона;
- архив;
- лаборатория;
- новые выставочные помещения.

Точные mechanics не утверждены.

# 20. Система прогрессии персонажа

Общее направление: progression должна быть **лёгкой и естественной**, без тяжёлого RPG skill tree с десятками ручных очков.

## Progression через действия

Часть характеристик развивается от того, чем герой реально занимается.

Например:

```text
много копает
→ растёт опыт раскопок
→ постепенно развивается stamina / эффективность

много использует конкретные инструменты
→ растёт соответствующий practical experience
```

Можно хранить скрытые или видимые counters:

- количество копков;
- объём выкопанного грунта;
- число экспедиций;
- количество найденных/оценённых предметов;
- другие реальные действия игрока.

После достижения определённых thresholds характеристика повышается автоматически.

То есть не обязательно:

```text
Level Up
→ +1 Skill Point
→ вручную нажать Strength
```

Предпочтительнее:

```text
игрок реально занимается деятельностью
→ получает практический progression
```

## Progression через городские здания

Некоторые направления можно ускорять или развивать целенаправленно через здания:

```text
Библиотека
→ знания / appraisal / dialogue / сделки

Спортзал
→ физическая форма / stamina

Парикмахерская
→ cosmetic changes, не характеристика
```

## Интеллект / знания

Библиотечная progression особенно связана с экономикой и социальными взаимодействиями.

Возможные эффекты:

- точнее определять цену находки;
- лучше понимать редкость;
- сложнее обмануть игрока при продаже;
- открывать более выгодные dialogue options;
- улучшать торг;
- легче располагать некоторых персонажей;
- получать дополнительные исторические сведения.

Точные названия stats и формулы пока не определены.

## Scope-принцип

Для таких действий не делать дорогие уникальные анимационные системы.

Можно использовать общий формат:

```text
войти в здание
→ выбрать действие
→ короткая стилизованная заставка / icon animation
→ timer / passage of time
→ применить результат
```

Это позволяет наполнить город активностями, не раздувая production scope.

# 22. Ближайшая design-задача

Не начинать пока detailed city architecture и NPC implementation.

Сначала:

1. выгрузить все накопившиеся идеи;
2. закончить список зданий;
3. закончить список ключевых NPC;
4. определить примерный lore города;
5. определить основные gameplay functions города;
6. только затем сделать первый city blockout в Unreal Engine.

Первый blockout:

- простые кубы;
- без финальных ассетов;
- музей;
- магазины;
- жилой квартал;
- общественные здания;
- улицы/проходы;
- проверка пеших расстояний.

Главный вопрос blockout:

> удобно ли игроку жить и постоянно перемещаться по этому маленькому городу?
