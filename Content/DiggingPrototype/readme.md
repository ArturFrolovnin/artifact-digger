# DiggingPrototype — копание областью, voxel 50 см

## Запуск
Откройте /Game/DiggingPrototype/L_DiggingTest и нажмите Play.
Направьте центр экрана на коричневую землю. Нажмите или удерживайте ЛКМ.
Пока ЛКМ удерживается, небольшой объём земли удаляется с интервалом не меньше 0,25 секунды.
Каждый шаг заново проверяет направление камеры: при повороте копание следует за взглядом.
Если земля стала слишком далеко, подойдите ближе или спуститесь в выемку.
Серые края и основание не копаются. Stop / новый Play восстанавливает участок.

## Что изменилось
Сохранены текущие BP_DiggableGround, компонент SoilBlocks, тестовый уровень, материал и mesh.
Новый прототип, новый персонаж или новая система управления не создавались.
- Ячейки уменьшены с 100x100x50 до 50x50x50 см.
- Участок остался 10x10x10 м: 20x20x20 = 8000 voxel вместо 2000.
- Вместо одиночного Remove Instance используется удаление сферической области одним Remove Instances.
- Добавлено удержание ЛКМ с ограничением частоты.
- Добавлена проверка расстояния от персонажа до точки попадания.
- Перед обращением к вводу/персонажу проверяются Is Valid для Player Controller и Pawn.

## Assets
- L_DiggingTest — существующий тестовый уровень прототипа, использует существующий BP_ThirdPersonGameMode.
- BP_DiggableGround — вся генерация земли, ввод, интервал, прицеливание и удаление.
- SM_SoilBlock — mesh куба с коллизией; для voxel используется масштаб (0.5,0.5,0.5).
- M_Soil — существующий коричневый материал.
Существующие игровые assets вне /Game/DiggingPrototype/ не изменялись.

## Параметры BP_DiggableGround
В разделе Digging доступны:
- DigRadius = 65 см — радиус сферы поиска экземпляров.
- DigInterval = 0.25 с — минимальный интервал между попытками копания.
- DigReach = 350 см — максимальное расстояние от позиции персонажа до Impact Point.
Используйте положительные значения; очень большие радиусы и очень маленькие интервалы увеличивают стоимость обновления коллизии.
NextDigTime — внутреннее время следующего допустимого действия; начальное значение 0.

## Генерация — Construction Script
SoilBlocks — один Instanced Static Mesh Component: Movable, BlockAllDynamic, без симуляции физики.
Clear Instances очищает прежнюю сетку перед перестроением.
Три вложенных For Loop проходят индексы X/Y/Z от 0 до 19 включительно.
Make Vector собирает индексы.
Transform Location с Make Transform переводит их в локальные центры:
X = -475 + 50 * X;
Y = -475 + 50 * Y;
Z = -25 - 50 * Z.
Второй Make Transform задаёт положение и масштаб (0.5,0.5,0.5), Add Instance добавляет voxel.
Границы объёма: X/Y от -500 до 500 см, Z от -1000 до 0 см.
Для изменения размера сетки нужно согласованно менять границы циклов, шаг, начальное смещение и масштаб.

## Удержание ЛКМ — Event Graph
Event Tick -> проверка существования Player Controller и Pawn.
Is Input Key Down(LeftMouseButton) OR Was Input Key Just Pressed(LeftMouseButton) -> Branch.
Is Input Key Down обеспечивает удержание; Was Input Key Just Pressed сохраняет короткие клики.
Get Game Time in Seconds >= NextDigTime -> Branch.
Если время наступило:
NextDigTime = Get Game Time in Seconds + DigInterval;
затем выполняется одна попытка копания.
Нет накопления серии отложенных действий: даже после длинного кадра выполняется не больше одного шага за кадр.
Частота ограничена интервалом и реальной частотой кадров.
После отпускания ввода следующая попытка не запускается. Повторные быстрые клики не обходят интервал.

## Прицеливание и область удаления
Get Player Camera Manager -> Get Camera Location / Get Camera Rotation -> Get Forward Vector.
Line Trace By Channel (Visibility):
Start = положение камеры;
End = Start + Forward Vector * 800 см.
Игрок исключён через Get Player Pawn -> Make Array -> Actors To Ignore.
Ignore Self = FALSE, потому что трассировка выполняется из актора самой земли.
Сначала проверяется попадание, затем Hit Component == SoilBlocks.
Distance(Vector) между Get Actor Location персонажа и Impact Point должна быть <= DigReach.
Таким образом, луч имеет запас 8 м для камеры ThirdPerson, но копать можно только в пределах 3,5 м от персонажа.

Get Instances Overlapping Sphere:
Center = Impact Point;
Radius = DigRadius (65 см);
Sphere In World Space = true;
Target = SoilBlocks.
Узел возвращает список индексов voxel, чьи ограничивающие сферы пересекают сферу копания.
Это приближённый сферический выбор, а не точное пересечение сферы с кубом.
Ограничивающая сфера куба 50 см имеет радиус примерно 43,3 см, поэтому центры выбранных voxel могут находиться до 108,3 см от Impact Point.
Это даёт округлую в плане ступенчатую выемку достаточной ширины для стандартной капсулы персонажа.
Удаляются целые voxel; плавное обрезание отдельных кубов не выполняется.
Следующий шаг заново трассирует уже изменённую землю, поэтому можно углублять выемку.

## Безопасное удаление ISM instances
Полученный список целиком передаётся в ОДИН вызов Remove Instances.
Нет цикла Remove Instance с возрастающими индексами.
Проверено по исходникам установленного UE 5.8:
UInstancedStaticMeshComponent::RemoveInstances копирует входной массив,
сортирует индексы по убыванию и вызывает RemoveInstanceInternal.
Поэтому изменение индексов при удалении не портит оставшиеся индексы этого действия.
Запрос сферы даёт уникальные актуальные индексы. Между запросом и удалением нет Delay или иных изменений компонента.
Индексы не сохраняются для следующего действия.
Remove Instances удаляет геометрию и соответствующие физические тела; скрытые блоки с оставшейся коллизией не используются.

1. В редакторе и PIE исходно 8000 экземпляров с масштабом 0.5 по всем осям.
   Первый центр (-475,-475,-25), последний (475,475,-975).
2. Первый щелчок: 8000 -> 7980, удалено 20 voxel.
3. Следующий щелчок с тем же направлением камеры: 7980 -> 7952, удалено 28 voxel.
   Луч попал в следующую поверхность примерно в (-350,50,-55.24).
   По координатам до/после рассчитана ожидаемая сфера: все 28 удалённых voxel соответствовали выборке, посторонних удалений — 0.
4. Проверено длительное нажатие штатной командой Unreal Input.+key LeftMouseButton,
   поданной через Slate MCP. Это симуляция удержания через реальный Player Input, а не прямой вызов удаления.
   Последовательные снимки без новых кликов: 7916 -> 7887 -> 7851.
   Дальше удаление прекратилось после исчерпания доступной в пределах дальности земли.
5. Input.-key LeftMouseButton отпустила кнопку.
   В последующей проверке число voxel осталось 7851, NextDigTime больше не обновлялось.
6. Персонаж физически прошёл с края в яму штатным вводом W через Input.+key / Input.-key.
   Для контролируемого теста изменялась только скорость runtime-экземпляра, без сохранения персонажа.
   После остановки движения центр капсулы стабилизировался примерно
   в (-400.85,-95.31,-57.85). Луч сверху подтвердил дно Z=-150 см.
   То есть персонаж стоит на земле на 1,5 метра ниже исходной поверхности.
7. Во время теста направление камеры фиксировалось только на runtime PlayerCameraManager;
   настройки исходного игрока и камеры не менялись.
8. В LogScript при проверке нет Accessed None, Infinite loop или Runtime Error.
9. PIE остановлен; временные настройки и выкопанные ямы сброшены.
   Blueprint скомпилирован, прототип сохранён, L_DiggingTest оставлен открытым.

Это проверка основной механики, последовательного пакетного удаления, удержания и коллизии.
Полное ручное прохождение всей глубины и длительные нагрузочные испытания не выполнялись.

## Ограничения
- Поверхность остаётся ступенчатой с шагом 50 см, а исчезновение voxel — мгновенным.
- Сфера выбирает ограничивающие объёмы, поэтому выемка несколько шире указанного радиуса.
- Нет обрушений: нависающие и отдельные voxel могут оставаться на месте.
- Один ISM содержит весь объём, включая скрытые внутренние кубы.
- Get Instances Overlapping Sphere просматривает экземпляры, а удаление обновляет коллизию синхронно.
  Для большого мира и очень частого копания нужны чанки и оптимизация.
- Копание локальное, без репликации и сохранения.
- Сохраняется существующая камера ThirdPerson; прицел не добавлен, целиться нужно центром экрана.
- Для выхода из глубоких ям нужно копать достаточно широкие ступени.
- Инвентарь, ресурсы, деньги, инструмент, частицы и звук не добавлены.

## Следующий шаг к действительно плавному грунту
Перейти от массива видимых кубов к полю плотности / signed distance field в чанках.
Кисть должна плавно уменьшать плотность вокруг Impact Point с затуханием по расстоянию.
Из плотности строить общую поверхность, например Marching Cubes или Dual Contouring.
Перестраивать только затронутые чанки и согласованно обновлять их collision mesh, желательно асинхронно.
Простое уменьшение кубов сделает ступеньки мельче, но само по себе не создаст действительно гладкую поверхность.
